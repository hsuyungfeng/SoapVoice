建立 `src/utils/metrics_collector.py`，實現 GPU/VRAM 指標收集機制。

**核心內容：**

1. **GPUMetrics dataclass** — 包含 timestamp、gpu_percent、vram_mb、queue_length、gpu_memory_total_mb
2. **MetricsCollector 類別** — 包含以下方法：
   - `__init__(update_interval: float = 2.0)` — 初始化，設定更新間隔（預設 2 秒）
   - `async start_background_task()` — 啟動後臺非同步任務，每 update_interval 秒收集一次指標；需要用 asyncio.Task 管理生命週期
   - `async stop_background_task()` — 優雅停止任務（設定停止旗標，待任務完成）
   - `get_latest_metrics() -> GPUMetrics` — 回傳最新收集的指標快照（不阻塞，無需 async）
   - `async collect_metrics()` — 單次收集邏輯（私有），調用 _get_gpu_metrics() + _get_queue_depth()

3. **GPU 指標收集** — 使用 pynvml（nvidia-ml-py）：
   - try: import pynvml，呼叫 `nvmlInit()` 初始化，`nvmlDeviceGetHandleByIndex(0)` 取得 GPU 0，`nvmlDeviceGetUtilizationRates()` 取得 GPU%/VRAM%，`nvmlDeviceGetMemoryInfo()` 取得絕對 VRAM 用量（MB）
   - except ImportError/nvmlError: fallback 回傳 gpu_percent=0.0, vram_mb=0.0, gpu_memory_total_mb=0.0（非致命）

4. **佇列深度探測** — `_get_queue_depth()` 私有方法：
   - 簡單實作：檢查全域變數 `getattr(app_context, 'pending_requests', 0)` 或直接回傳 0（Placeholder 可後續調整）
   - 或使用 asyncio 任務計數（if needed）

5. **Thread-safe 最新指標存儲** — 使用 `asyncio.Lock` 保護 `self._latest_metrics` 更新

6. **容錯設計**：
   - pynvml 初始化失敗時不拋例外，只記 warning log
   - GPU 查詢失敗時回傳合理預設值（0 或上次有效值）
   - 指標收集任務崩潰時自動重試（加入 try-except + logger.error）

**範例驅動：** 後臺任務執行 while 迴圈，檢查 self._stop_event.is_set()，若未設則執行 await asyncio.sleep(update_interval) 後調用 collect_metrics()。

建立 `src/api/metrics_api.py`，提供兩個端點與必要的 DB 整合。

**1. SSE 端點 — GET /api/v1/metrics/stream**
- Content-Type: `text/event-stream`
- 使用 sse-starlette `EventSourceResponse` 或原生 `StreamingResponse`
- 非同步產生器逐次推送指標
- 迴圈邏輯：
  - 每 2 秒呼叫 metrics_collector.get_latest_metrics()
  - 格式化為 SSE 格式 "data: {json}" + "\n\n"
  - yield 該行
  - 若用戶斷線（CancelledError），優雅結束
- 無認證要求（診所內部 LAN，後續可加 CORS/IP 白名單）

**2. 歷史查詢端點 — GET /api/v1/metrics/history**
- Query params: `granularity: str = "minute"`（"minute" / "hour" / "day"）、`limit: int = 100`
- 回傳最近 N 筆歷史指標，按時間排序
- Response: 
  ```json
  {
    "metrics": [
      {
        "timestamp": 1234567890.5,
        "gpu_percent": 45.2,
        "vram_mb": 2048.5,
        "queue_length": 3
      }
    ],
    "granularity": "minute",
    "total": 100
  }
  ```

**3. DB 整合**
- 擴展 `src/db/patient_records_db.py` 的 `init_schema()` 函數，新增 metrics_history 表（冪等式 CREATE TABLE IF NOT EXISTS）：
  ```sql
  CREATE TABLE IF NOT EXISTS metrics_history (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    timestamp REAL NOT NULL,
    gpu_percent REAL NOT NULL,
    vram_mb REAL NOT NULL,
    queue_length INTEGER NOT NULL,
    created_at TEXT DEFAULT CURRENT_TIMESTAMP
  )
  ```
- 在 `metrics_collector.py` 的 `collect_metrics()` 中新增邏輯：在收集指標後，透過非同步函式 `save_metrics_to_db()` 插入 metrics_history 表
- save_metrics_to_db() 函式應在 patient_records_db.py 中定義，避免循環依賴

**4. 路由註冊**
- 在 `src/main.py` 中 include_router(metrics_router, prefix="/api/v1")
- 須在其他路由（especially WebSocket router）**之前**註冊，避免路由衝突

**5. lifespan 整合**
- 在 `src/main.py` lifespan 中，`yield` 前啟動 MetricsCollector：
  ```python
  try:
    from src.utils.metrics_collector import MetricsCollector
    metrics_collector = MetricsCollector(update_interval=2.0)
    await metrics_collector.start_background_task()
    app.state.metrics_collector = metrics_collector
    logger.info("Metrics collector started")
  except Exception as e:
    logger.warning(f"Failed to start metrics collector: {e}")
  
  yield
  
  # cleanup
  try:
    await metrics_collector.stop_background_task()
    logger.info("Metrics collector stopped")
  except Exception as e:
    logger.warning(f"Failed to stop metrics collector: {e}")
  ```

**錯誤處理**
- SSE 端點若收集指標失敗，記 warning 但繼續推送上次有效值（不中斷 stream）
- DB 寫入失敗時記 warning，不影響 SSE 推送

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → SSE Endpoint | Untrusted HTTP client (LAN) — metrics stream carries no PII but resource-intensive |
| Backend → GPU/pynvml | Trusted system library; fallback safe if unavailable |
| Backend → SQLite | Trusted local database; metrics are non-sensitive operational data |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-01 | Spoofing | SSE endpoint (no auth) | Mitigate | Add IP whitelist (LAN 192.168.x.x / 10.x.x.x) via middleware in Task 2 |
| T-12-02 | Information Disclosure | Metrics in SQLite | Accept | Metrics are non-sensitive (GPU%, queue length); no PII or medical data |
| T-12-03 | Denial of Service | SSE stream resource consumption | Mitigate | Limit concurrent SSE connections via app.state counter; log excessive connects |
| T-12-04 | Tampering | metrics_history table | Mitigate | Read-only historical queries; no UPDATE/DELETE endpoints |

</threat_model>
